# AIRI 修改的持续记录约定

用户明确要求：本聊天中的 AIRI 配置、修改和调试全部记录到这个 GitHub 项目。
后续接续工作应沿用此约定，完成脱敏代码、过程和验证记录，再提交已审公开内容。

用户随后进一步明确：GitHub主要是记录已经验证可用的路径和方法。每次调试应提炼成可执行方法、适用条件、验证证据与必要陷阱；不堆聊天和时间流水。尚未验证的修改单独列待验收，不能混进成功方案。[已验证操作手册](verified-paths.md)是主入口。

每项变更保留足够让另一位开发者或其 AI agent 继续的信息：

- 具体触发条件、原行为与目标行为，以及当前完成状态。
- 实际改动的程序、可复用配置模板和调用方式；用户路径改成参数或示例变量。
- 模型／素材的官方来源 URL、版本或哈希、所需格式与许可边界；需要下载时给正常获取流程或脚本。
- 执行过的测试、失败结果、修复依据、通过证据与尚未执行的目标应用检查。
- 更新或回退时需要保留的用户自定义内容；源码与个人设置分开。

公开程序和过程，不公开个人设置快照、令牌、API 密钥、聊天、私人画面、已登录 profile、
官方受限图片／派生纹理／模型包、Core 或权重。配置模板应能审阅，不依赖原开发者主目录。
素材可获取不等于允许二次打包；权利人限制的视频用途也不自动授权桌宠用途。

## 两种表情能力要分开

1. **Live2D 面部表情**由 model3 的 `Expressions`与精确名称的 ACT 控制，改变眼、眉、嘴或姿态。
2. **聊天表情包／贴纸**是 AIRI 聊天界面的另一项配置，需要核实其实际设置、资源格式、触发与显示。

优先搜索官方表情包、官方账号和官方素材配布。只发布官方 URL、来源与获取/配置代码，
不把受限贴纸本体放进程序包。分别记录“配置已写入”“实际聊天显示通过”或“尚未测试”，
不能用已验证的12个Live2D表情代替贴纸验收。

当前贴纸制备/store导入helper已验证并有公开代码/来源；实际主app导入、设置与缩略图显示已验，真实聊天选图仍待验。官图2D、站姿2D和用户自有3D作为三张独立卡接续；用户自有3D实际注册/激活/显示通过，原创自然待机已接入并前台可见，物理音频联合另验。两套时装用户明确暂缓，不列当前欠缺或阻塞。见[已验证方法](verified-paths.md)。
